# Домашнее задание к занятию «Репликация и масштабирование. Часть 2» Хайретдинов Тимур

### Задание 1

Опишите основные преимущества использования масштабирования методами:

- активный master-сервер и пассивный репликационный slave-сервер; 
- master-сервер и несколько slave-серверов;

Ответ:
- Активный master и пассивный slave повышают отказоустойчивость: при сбое master можно быстро переключить нагрузку на реплику. Slave также можно использовать для резервного копирования и проверок.
- Один master и несколько slave прежде всего масштабируют чтение: запросы распределяются между репликами, разгружая master для операций записи. Это повышает производительность, позволяет обслуживать больше пользователей и даёт дополнительную устойчивость: при выходе одной реплики из строя остальные продолжают отвечать.

### Задание 2


Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц: 

- пользователи, 
- книги, 
- магазины (столбцы произвольно). 

Опишите принципы построения системы и их разграничение или разбивку между базами данных.

*Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.*

1. Вертикальное разбиение: по предметным областям

- `users_core` - `user_id`, логин, хэш пароля. Отдельное масштабирование аутентификации и аккаунтов
- `users_private` -	`user_id`, имя, email, телефон, адрес -	перс данные хранится в изолированном контуре с ограниченным доступом
- `books` -	`book_id`, название, автор, жанр, цена, статус -	Каталог книг
- `stores` - `store_id`, регион, город, адрес, координаты, режим работы -	географическая локализация магазинов

2. Горизонтальное разбиение: внутри каждого контура

- `users_core` и `users_private` делятся по `hash(user_id)`. Один пользователь всегда попадает в один и тот же шард обоих контуров.
- `books` делится по `hash(book_id)`.
- `stores` делится по региону (RU, EU, …); внутри крупного региона возможно дополнительное деление по `hash(store_id)`. Такой ключ полезен для запросов поиска магазинов.

3. Режимы работы серверов
- Shard Router - несколько экземпляров без состояния, принимают запросы и направляют их в нужную БД.
- Primary каждого шарда - read-write. Выполняет все изменения в рамках своего шарда.
- Реплики - read-only. Обслуживают поиск книг, карточки пользователей и списки магазинов; разгружают primary.
